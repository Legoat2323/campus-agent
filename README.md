# 校园新生问答 Agent

一个面向大一新生的校园问答服务。问报到时间、快递点在哪、图书馆能借几本书这类问题，
它会从整理好的资料里找答案，找不到就说没有。

后端 FastAPI，知识库用 Chroma，模型是智谱 GLM-4-flash。

## 为什么做这个

新生入学前后问题特别碎：几点报到、从火车站怎么走、被子要不要带、学费怎么交。
这些信息散在学校官网、公众号、学长学姐的聊天记录里，哪个都不好找。

我自己刚经历完这一轮，把踩过的东西整理下来做成一个能问的机器人。
目标不是做一个比搜索引擎更强的东西，而是把"我们学校自己的经验"收拢到一个地方。

## 现在能做到什么

- 40 条问答，分成四个主题：报到前、报到当天、入学第一周、校园生活
- 网页界面，回答是流式输出的（一个字一个字出来），不是等半天弹一整段
- 能调天气工具（问"今天天气怎么样"会走 Function Calling）
- 记得上下文，能追问
- 不会瞎编：资料里没有就直说没有

我用 8 个问题测过（4 个主题各 2 条），检索和回答都是 8/8。
测试脚本在 `test_qa.py`，你可以自己跑。

### 天气工具

真实的天气查询，数据来自 Open-Meteo（免费、无需 API key），带 10 分钟缓存。

踩过的坑：Open-Meteo 对中文地名识别很差，搜「桂林」返回的是安徽/福建的同名村，
必须用拼音 `Guilin` 才能匹配到桂林市。所以 `weather.py` 里内置了常用城市别名表。

## 数据从哪来

`data/` 下有 4 个 markdown 文件，一共 40 条。

**官方能查到的**（报到时间、学费、档案、户口）来自学校招生网的
[2026 年新生入学须知](https://www.guet.edu.cn/zs/2026/0728/c2214a158488/pagem.htm)，文件头写了来源。

**官方查不到的**（快递点分布、宿舍门禁时间、图书馆规则）是我自己整理的，
比如快递点分三处：前街是邮政，后街是中通申通和多多驿站，F 区篮球场旁边是顺丰京东极兔。

这类信息才是这个项目里真正有用的部分——网上搜不到，通用大模型也不知道。

有几条我确实不知道，标了"待确认"，没编。包括绿色通道的具体流程、宿舍分配规则、校园卡怎么办。
以后打听到了再补。

数据是 2026 级的，明年日期和电话可能要改。

## 怎么跑

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

新建 `.env`，写一行：

```
ZHIPU_API_KEY=你的key
```

然后建库、启动：

```powershell
.\.venv\Scripts\python.exe build_db.py
.\.venv\Scripts\python.exe main.py
```

打开 http://127.0.0.1:8000 就是界面，http://127.0.0.1:8000/docs 是接口文档。

> 注意别直接敲 `python`，要用 `.\.venv\Scripts\python.exe`。
> 系统的 Python 没装这些依赖，会报 ModuleNotFoundError。

## 几个设计上的选择

### 按 `##` 切分，不用固定长度

一般做法是 `chunk_size=500` 按字数硬切。我一开始也这么写，结果一句话能被切两半，
检索出来是残缺的。

后来改成按 markdown 的 `##` 标题切：写数据时一条事实一段，切出来一条就是一块。
既不会被切碎，也不会把不相关的内容混在一起。

代价是数据必须写规范，标题乱了就切不对。

### 知识库按时间线分，不按部门分

学校的信息一般是按部门组织的：教务处管的、学工处管的、后勤管的。
但新生不会这么想，他只会想"我现在该干什么"。

所以四个文件是按报到进程排的：报到前、报到当天、第一周、之后的生活。

### 怎么控制模型瞎编

这是这个项目花时间最多的地方。

一开始问"学校附近有啥好吃的"，它编出了五家不存在的店，还自己写了一句
"以下推荐以虚构的学校为例"，然后接着编。

第一反应是改 prompt，加了几条规则：只依据资料回答、资料里没有就说没有、禁止编造店名。
**但没用。** 因为检索永远会返回 top-2，哪怕完全不相关，context 也不为空，
模型看到"食堂"两个字，就觉得这题能答，于是开始扩展。

后来改成用分数卡：`similarity_search_with_score` 会返回距离，越小越相关。
把距离超过阈值的片段直接丢掉，context 空了就返回一句固定的话。

阈值没拍脑袋定。我写了 `test_scores.py`，测 4 个库里有的问题（最差 0.87）
和 3 个库里没有的问题（最好 1.18），中间空档挺大，所以取 1.0。

改完再问"附近有啥好吃的"，它会说"这个问题我这边没有相关资料"。
问"快递点在哪"还是正常回答，没被误伤。

### 为什么没做重排和意图路由

我的招投标项目里做了查询重写、混合检索和 rerank，因为那边有 896 个切片、
用户说"价格"而文档写"投标报价权重"，不用这些根本召回不到。

这个项目只有 40 条，向量检索实测 100% 命中。这时候再加重排，只会上线延迟和多一个出错的地方。
等以后数据涨到 200 条以上再说。

## 踩过的坑

**测试脚本骗了我。** 第一次跑测试，检索显示 7/8，但回答是 8/8。
按理说检索没命中，模型不可能答对。查下来是我的关键词写的是"9月5"，
数据里是"9 月 5 日"，多了空格，字符串匹配失败。改成正则去掉空白就是 8/8。

这件事提醒我：指标异常的时候，先怀疑指标本身。

**改了代码没反应。** 改完 prompt 重启，发现没变化，最后发现是在另一个目录的
同名文件里改的。后来养成习惯，改完先看路径对不对。

**commit 信息乱码。** PowerShell 里提交中文信息，git 收到的编码不对，历史里是乱码。
现在 commit 信息统一用英文。

## 还没做的

- 三条"待确认"还没补，得去问学长
- 出错时返回 `{"error": ...}` 但 HTTP 状态码还是 200，应该用 HTTPException
- 没做鉴权、没限流、没配 CORS，只能本地跑
- `langchain_community` 里的 Chroma 已经废弃了，要迁移到 `langchain_chroma`
- 孤儿会话没有清理策略（按 30 天过期之类）
- 指代参考只在"最近 4 条 + 摘要"里找，再久之前的指代会因为摘要变粗而丢掉

## 查询改写（D4，指代消解）

用户第二句常是“刚才那个电话是多少”——句子里没有“招生办”，向量和 BM25 都抓不到。

做法：检索前先用一次模型调用，把带指代的问题按【对话历史】补全。

- `main.py` 的 `REWRITE_PROMPT`：明确要求“改写后不许再出现指代词”，并给一个正例 + 一个反例
- `rewrite_query()`：没有历史就跳过（第一轮不多花一次调用）；改写失败或长度不在 2–60 字就退回原句
- 给模型的 user message 仍是**原问题**，只有检索用改写后的句子
- 开关：`ENABLE_QUERY_REWRITE`

实测（`verify_d4.py`，同会话两轮）：

| 配置 | 第 2 轮检索 | 第 2 轮回答 |
|---|---|---|
| 关闭改写 | ❌ context 0 字 | ❌“没有相关资料” |
| 打开改写 | ✅ context 172 字 | ✅“招生办的电话，号码是0773-2290010” |

代价：多一次模型调用（只在**有历史**时发生）。回归 20 题 17/20、holdout 5/5 无变化。

第一版 prompt 只写了“用历史补全”，模型偷懒只删了“那个”（`刚才那个电话多少` → `刚才的电话多少`），带着指代词就返回了；
加了“不许再出现指代词”的硬规则和反例示例之后才改对。**提示词里的反例比正例更管用。**

## 已知边界（写在前面，别被追问打穿）

### 4 轮以内、检索又落空时，会被兜底拦掉（已知缝隙）

兜底条件是「没调工具 + 检索为空 + **没有摘要**」。所以有摘要才放行——
这就留下一个缝隙：**只聊了 2–4 轮（messages 里有、但还没到 8 条、没生成摘要）时，如果检索落空，代码仍然直接返回"没有相关资料"**，
哪怕上一句刚答过这个问题。

真实场景：

```
第1轮：招生办的电话是多少？  → 0773-2290010（就在 messages 里）
第2轮：刚才说的那个电话是多少？ → 改写失败 / 检索落空
      → context 空 + 没摘要 → 短路 → "没有相关资料"
```

**为什么明知有洞也不放宽**：把条件改成"有历史就放行"，等于让 B 组那 8 道"库里没有答案"的题在聊天中也被送到模型面前，
拒答就从"代码保证的 8/8"退化成"prompt 保证的看运气"。**用确定性强项换边角情况，不划算。**

正确方向不是放宽放行条件，而是**提高改写的可靠性**（例如改写失败时，用「上一条用户消息 + 当前问题」拼起来再检索一次）。
先把不确定的那层做稳，再放宽确定的那层。

### 改写本身也会失败，而且"看见历史"不等于"会用历史"

第一版 `REWRITE_PROMPT` 只写了"用对话历史补全"，模型把

```
刚才那个电话是多少？  →  刚才的电话是多少？
```

只删了"那个"，指代词"刚才"还在，检索依然 0 命中。加了**"改写后不许再出现任何指代词，出现就说明没做完"** + 一个反例示例之后才改对。

失败可能出现在五个地方，所以代码里设了三道闸：

| 失败点 | 处理 |
|---|---|
| 模型偷懒/改错 | prompt 硬规则 + 反例（人肉兜） |
| 输出空/超长（不在 2–60 字） | 退回原句 |
| 调用超时/限流 | `except` 退回原句 |
| 改对了但文档用词不同（招办 vs 招生办公室） | 无解，只能接受 |
| 检索到但距离 > `MAX_DISTANCE` | 阈值拦掉 |

**原则：改写是锦上添花，失败就退化成"没有改写"，不能一票否决。** 下限不动，上限抬高。

另外，"那个/它"这种指代本身可能有歧义（前面提过招生办、又提过图书馆，"它周末开吗"指哪个？）。
模型只能猜，猜错比不改更糟——会检索到错的东西并给出自信的错误答案。所以改写只在**有历史**时触发，第一轮一律跳过。

**会话聊过 5 轮以上（超过 8 条消息）之后，这个 session 就不再走"无资料兜底"了。**

原因：压缩会产生摘要，而兜底条件是"没调工具 + 没检索到资料 + 没有摘要"。有摘要就放行给模型，
否则模型看不见摘要里早就说过的事（"刚才那个电话是多少"会答不出来）。

代价：同一个 session 里再问文档外的问题，模型会硬答（可能编），不再直接回"没有相关资料"。
守门的是 prompt 规则 1/2（只依据资料、没有就说没提），实测 20 题开发集 A 9/12、B 拒答 8/8 没有退化。

## Docker 部署

```bash
# 构建（依赖层有缓存；首次联网装依赖约 3-4 分钟，用清华源）
docker build --build-arg PIP_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple -t campus-agent .

# 运行（挂载代码目录：改代码不用重建镜像）
docker run --rm -p 8000:8000 --env-file .env -v "${PWD}:/app" campus-agent

# 浏览器打开 http://127.0.0.1:8000
```

**两个细节**

- `-v "${PWD}:/app"` 把本目录挂进容器：改 `main.py` 后重启容器即刻生效，且 `memory.db` 天然持久化
- 上线时去掉这个挂载，用镜像里的代码（`docker run -p 8000:8000 --env-file .env campus-agent`）

**踩过的坑**

1. `requirements.txt` 原为 UTF-16LE，Linux 下 pip 报 `Invalid requirement: '\xff\xfea'` → 转 UTF-8
2. 在 `C:\Users\...` 下 build 会报 `open Dockerfile: no such file` → 先 `cd` 到项目目录
3. `--build-arg PIP_INDEX` 变了会击穿缓存、重装全部依赖 → 每次用同一个源
